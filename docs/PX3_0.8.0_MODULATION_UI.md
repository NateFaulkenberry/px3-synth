# PX3 0.8.0 in-window modulation UI

Decision 3 of `PX3_0.8.0_RECONSTRUCTION_AUDIT.md`: no instrument functionality
in separate windows. The floating ROUTES window (`GraphRouteWindow`,
`GraphRouteEditor`, `GraphCableCanvas` in `ModPanel.cpp`) is deleted. Modulation
is patched, seen and edited inside the main editor.

### Sources and jacks

Eleven sources, in graph order: LFO 1-3, ENV 1-3, MACRO 1-5. Each has a fixed
colour (`modrouting::sourceColour`) used by its jack, its cables, its list row
and the rings it draws on knobs. A jack shows a filled centre once it has at
least one route.

Jacks live in three places, all driving the same `ModDragController`:

- the **patch bar** (`MOD  LFO 1 ... M5`), a 30 px strip under the panels on
  every page except SETTINGS;
- the top-right corner of each **LFO and ENV card** on the MOD page;
- the left column of the MOD page's **patch view**.

### Patching

Press on a jack and drag. A cable follows the pointer over the whole editor.
Any knob whose parameter is a graph destination (`isGraphDestination`, i.e.
the catalog's `modulationDestination` flag) highlights with the source colour
and a "LFO 1 > Filter 1 Cutoff" tag; release to create the route (a free slot
of the 64, depth +50%, NATIVE, LINEAR). Dropping the same source on the same
knob again does not duplicate it. Nothing happens over a non-destination.

There is no list of targets: the controller walks the editor's component tree
for the deepest visible slider stamped with a parameter id (the same stamp MIDI
learn uses), so every modulatable knob on every page is a target, including
fine tune (`voice.oscN.tuning.cents`) and the new SLOP / KEY TRACK knobs.

To reach a knob on another page, dwell on its tab while dragging (about 0.4 s):
the tab opens under the cable (spring-loaded tabs). Starting from the patch bar
usually makes that unnecessary.

### Seeing routes

- **Rings.** Every knob with routes draws one arc per route (up to three,
  stacked outwards) in the source's colour, spanning the normalised range the
  route can sweep from the knob's current position (bipolar sources: centred;
  unipolar: one side, signed by depth), plus a small dot at the lower left.
  The existing live "modulatedPos" arc and dot still show where the value is
  right now.
- **MOD page.** The LFO/ENV cards keep the left of the page; the right is the
  ROUTING panel: a patch view (jacks on the left, one node per routed
  destination on the right, a hanging cable per route, thicker for more depth)
  and a list of every route.

Routes made with the LFO/ENV cards' ASSIGN menus ("CARD ASSIGN") and macro
destinations ("MACRO") are shown too, so the page is the complete picture.

### Editing

Each list row: `SOURCE > Destination`, its origin (SLOT n / CARD ASSIGN /
MACRO), an X button, a depth bar (-100..+100%, double-click resets to 0),
polarity (NATIVE / UNIPOLAR / BIPOLAR) and curve (LINEAR / SQUARE / SQ ROOT).
For graph routes the depth bar is attached to `mod.routes.slotNN.depth`, so it
is automatable and undoable by the host. Card routes edit the card's AMOUNT;
macro routes edit the macro depth. Polarity and curve apply to graph routes.

Click a row or a cable to select it (highlighted in both views); Delete or
Backspace removes it.

## Cost

- One pass per 30 Hz tick: `collectRoutes` (64 slots + 6 card assigns + macro
  destinations) and a map of ring data by parameter id. The knob walk that MIDI
  learn already runs compares each knob's ring data and repaints only on a
  change. Knobs without routes carry no property and draw nothing extra.
- The routing panel refreshes only while visible, and rebuilds its rows only
  when the set of routes, a polarity or a curve changes.

## Tests

`PX3Tests editorlayout`, `ModRouteUi_*` (17): a simulated mouse drag from a
patch-bar jack onto FILTER 1 CUTOFF creates the route at +50%; the routed knob
carries a ring in the source colour and an unrouted one carries none; ENV 1
onto OSC 1 FINE; a drop on a non-destination creates nothing; the routing panel
is a child of the editor on the MOD page; a card jack patches a knob; the list
shows every route; the row's depth bar writes the depth parameter; polarity and
curve; select + Delete removes the route and its ring; the patch view draws
cables; and the number of desktop components and top-level windows is the same
before and after all of it (no window is ever opened).

`PX3_SNAPSHOT_ROUTES=1 PX3Tests uisnapshot <dir> 1518 918` renders the
sections with four demo routes.
