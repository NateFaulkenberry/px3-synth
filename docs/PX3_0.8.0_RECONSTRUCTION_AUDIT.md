# PX3 0.8.0 Reconstruction: Audit and Progress

The owner's reconstruction brief (2026-10-03) supersedes the hardware-look
direction in `PX3_0.8.0_ARCHITECTURE_ASSESSMENT.md`. The new direction:

- A VCV Rack-inspired modular workspace in a single main window.
- No instrument functionality in floating windows.
- A real live layout editor that is compiled out of release builds.
- Every DSP feature traced from UI → parameter → DSP → output.

Paused release-gate results are in `PX3_0.8.0_RELEASE_GATES.md`.

Status vocabulary: fully / partial / placeholder / superficial / incorrect /
not implemented.

## Phase 1 audit

### Filters, modulation, envelopes

| Feature | Status | Evidence | Fix direction |
|---|---|---|---|
| Resonance / self-oscillation | Partial: no whistle, no self-oscillation | Param range 0.25..2.2 (`PluginProcessor.cpp:241`); DSP clamps Q to 0.2..10 (`VoiceFilter.cpp:47`); ladder resonance maps to ≤0.95, so k≈3.8 < 4 (`FilterResponse.h:35`) | Widen the user range. Let the ladder reach self-oscillation with saturation in the feedback path. Add a drive control |
| Ladder | Partial: real 4-pole, but a JUCE `LadderFilter` wrapper | `VoiceFilter.h:55`; drive fixed at 1.0 (`VoiceFilter.cpp:22`) | Own ZDF/Huovilainen ladder with drive, resonance compensation, optional 2× oversampling |
| Curtis (CEM3320-style) | Not implemented | `FilterMode.h:9-21` | New OTA-cascade 4-pole mode |
| ARP 2-pole vintage | Not implemented | — | New aggressive 2-pole (resonant SVF with asymmetric saturation) |
| Keyboard tracking | Not implemented | No key field in `FilterTypes.h:9`; cutoff in `SynthVoice.cpp:449` has no note term | Per-voice `cutoff × 2^((note−ref)/12 × amount)`, amount −100..+200%, reference key |
| Filter modes offered | Fully | 12 modes: LP/HP/BP/Notch/AP biquads, LP/HP24, Comb, SVF12/24 (JUCE TPT, LP only), Ladder12/24 | Rework the list around the new models |
| LFO free / tempo / transport | Mostly | `PluginProcessor.cpp:728`, `LfoGenerator.cpp:34-95` | Add MIDI clock (0xF8) where practical; add a unipolar option; add random and S&H waves |
| Modulation graph | Partial: **global per-block only** | `ModulationGraph.h`; ENV values are averaged over voices (`PluginProcessor.cpp:1572-1625`); `ModulationScope::voice` is unused | **Needs per-voice evaluation** for ENV/key/velocity/slop sources. This is the main architectural gap |
| ENV → LFO params, ENV → ENV params | Fully (global) | `ParameterCatalog.cpp:244`; cycle rejection in `ModulationGraph.h:107` | Becomes per-voice with the item above |
| Mod → fine tune (cents) | Partial | Fine ±24 c is a destination, but modulation is global so every voice moves together | Per-voice slop/random source |
| Random / analog slop | Superficial | Only VIBE drift per voice (`SynthVoice.cpp:775`), not a graph source | Per-voice random/drift source with a cents-scale depth |
| Envelope loop / key tracking / sync | Not implemented | ADSR plus a one-shot breakpoint mode only | Add loop, key → time scaling, tempo-synced times |
| Series/parallel filter routing | Fully | `SynthVoice.cpp:1034` | Keep |

Other notes:
- `docs/MODULATION_AND_FILTER_ROUTING.md` §8 is stale: it says tempo sync is
  absent, but TEMPO/TRANSPORT now exist.
- No tests cover per-voice ENV values, key tracking or self-oscillation.
