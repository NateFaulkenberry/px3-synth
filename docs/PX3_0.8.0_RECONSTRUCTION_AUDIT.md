# PX3 0.8.0 Reconstruction: Audit and Progress

The owner's reconstruction brief (2026-10-03) supersedes the hardware-look
direction in `PX3_0.8.0_ARCHITECTURE_ASSESSMENT.md`. The new direction:

- A VCV Rack-inspired modular workspace in a single main window.
- No instrument functionality in floating windows.
- A real live layout editor that is compiled out of release builds.
- Every DSP feature traced from UI → parameter → DSP → output.

Paused release-gate results are in `PX3_0.8.0_RELEASE_GATES.md`.

Status vocabulary: fully / partial / placeholder / superficial / incorrect /
not implemented.

## Phase 1 audit

### Oscillators

`OU` = `products/PX3Synth/DSP/OscillatorUnit.cpp`, `PP` = `PluginProcessor.cpp`.

| Feature | Status | Evidence / root cause | Fix direction |
|---|---|---|---|
| Octave / semitone / cents | Fully | `*.tuning.coarse/semitone/cents` (±2 oct, ±12 st, ±24 ct) for osc1-3 and sub; modulatable; `OscillatorTuning.h` ratio applied per block (`SynthVoice.cpp:500`); tested | Keep. Consider widening cents to ±50 or ±100 |
| Supersaw Spread → Detune | Partial | Seven saws at ±3.5 st at full spread; cost does not depend on spread; no DSP failure. The "degradation" comes from voice management, which ignores cost: stealing off (`PP:1018`), tail pruning caps 4/8/10, a 48-voice sounding budget, and the polyphony gain ducking to 0.10 for wide uncorrelated saws with a 2.5 s recovery (`PP:2086-2260`) | Rename the label. Make the budget cost-weighted per mode. Re-tune the polyphony-gain prediction for decorrelated sources. Add a many-voice test at spread = 1 |
| Hard Sync drive | Partial | Drive is 1..3.3 via tanh-ADAA (`OU:~479, ~900`): correct but mild | Range to about 10, with level compensation and asymmetric bias for character |
| Organ Click | Superficial | Burst of at most about 0.13 (−18 dB), 6–35 ms, mostly noise, then clipped (`OU:~1000`) | Louder pitched key-click transient plus noise, about 50–120 ms, key-tracked |
| Digital | Partial | BITS = 2..16 (phase plus output crush). RATE = integer sample-hold **and** wavefolder, coupled (`OU:~486`) | Separate RATE (fractional, Hz-based) and FOLD; label it like Logic's Bitcrusher |
| Physical Material | Partial (by design pitch-stable) | Mode 0 stays fixed; only upper partials spread (`OU:1052`). The perceived pitch change comes from the spectral centroid moving | Redesign as material (stiffness/damping/formant) and keep the centroid change audible but not pitch-like |
| Rob Body / Chaos | **Incorrect** | The main fundamental runs at `increment × (1 + 1.05 chaos + 0.45 body)`, up to 2.5× (about +22 st) (`OU:1085-1145`) | Keep the fundamental at the note. Body = spectral density; Chaos = grain/S&H stochastic modulation |
| Isaac Stretch | **Incorrect** | Ratio `h(1 + 0.033h·inh)` detunes h=1 by +56 ct (`OU:419`) | Use `(h−1)` so the fundamental is locked |
| Custom wavetables | Partial | Drag-drop only. WAV/AIFF/images go through `WavetableImporter`; failures are reported; saved as `.px3wt`. **No file picker, no preview, a missing table renders silence** (`OU:~648`) | Import… FileChooser, a preview, a factory fallback, delete/rename |
| Slop / drift | Partial | Only VIBE drift, shared across the voice's oscillators (±60 ct, `SynthVoice.cpp:773`) | Per-voice, per-oscillator slop as a modulation source, scaled in cents |

Regression risks: Rob/Isaac/drive/click changes alter factory presets and
the polyphony gain calibration. Range changes alter saved normalized
values, which is acceptable because 0.8 has no compatibility requirement.

### FX

**Chain.** The order is Vibe (no-op stage; Vibe runs per voice), Chorus, Doom,
Lucy, Delay, Mood, Reverb, Spread (`FxChain.h`). The chain processes the
**FX send sum**. The return is `(stage − fxIn) × headroom × return fader`, so
no FX touches the dry bus.

| Effect | What it really does | Status vs request | Root cause / fix direction |
|---|---|---|---|
| Vibe | Per-voice "analog imperfection": slow drift of pitch (≤32 ct) and cutoff, saturation, noise; 6 types | Not Uni-Vibe-like | Small tonal impact by design (sub-audible drift). Add a real Uni-Vibe stage: 4 staggered allpasses plus an asymmetric lamp LFO, with chorus/vibrato. Keep the drift as the source of per-voice slop |
| Chorus | Dimension-D style anti-phase pair with BBD colour; 8 DIM/ensemble modes | No Juno I / II / I+II | Add Juno-style modes: one BBD line per side, triangle LFO about 0.5 Hz (I) and 0.8 Hz (II), I+II stacked |
| Doom | MOOD-style wet channel plus looper. **GLUE is always on (0.15)**: drive `1+7g`, tanh, a wavefolder above 0.5, a squash above 0.8, on the whole output (`Doom.cpp:~1435`) | Clipping above about 50% explained | Gain-stage GLUE: unity-gain soft saturation curve, the fold only as an explicit option, oversampled, makeup by RMS |
| Lucy | Lossy-style STFT degrader: bin dropping (LOSS, MODE), packet dropouts/repeats, spectral freeze, filter, reverb, gate, limiter. GLOBAL is the amount (default 0) | Works, unclear UI | Rename and tooltip: e.g. "LOSS" → "CODEC LOSS", THRESHOLD → "LIMIT", FREEZER, WEIGHT |
| Delay | 7 algorithms; granular CLOUD/SHIMMER do recirculate | Granular feedback exists. **Tape wow/flutter is hard-coded at 0.55** (`Delay.cpp:~1130`); no mod depth | Add WOBBLE, TAPE QUALITY and MOD DEPTH params; fold Mood's slip into Tape as a reverse/slip head |
| Mood | MOOD-style looper plus wet (REVERB / DELAY / SLIP). SLIP loops a pitch-shifted 0.05–0.55 s window | Overlaps Delay/Reverb | Investigate moving tape slip into Delay before any removal. Enabled at mix 0.35 by default, unlike the other FX |
| Reverb | ROOM / PLATE / HALL / CLOUD FDNs | No IR, no shimmer | Shimmer: octave pitch-shifter in the CLOUD feedback path. IR: `juce::dsp::Convolution` loaded off the audio thread |
| Spread | Band-split allpass widener with mono-safe low band, correlation guard | **Inert by default**: amount 0 (`PluginProcessor.cpp:638`) gates every control, and it only sees the FX send, so it can never widen the dry signal | Move to a master-bus stereo stage, give it a sensible default, cut the surface to WIDTH / LOW-MONO / MIX |
| Distortion | None dedicated | Not implemented | New oversampled drive stage: diode/op-amp soft clip, asymmetric option, tone, level |

**Unclear labels:**
- Doom: GLUE (it is the distortion), CROSS, BLEND, FADE, two MODIFY controls.
- Lucy: WEIGHT, FREEZER, V-PRE/V-POST, THRESHOLD.
- Chorus: SPREAD vs WIDTH, MIX vs AMOUNT, CHARACTER.
- Spread: LOW/HIGH XO, CENTER.
- Reverb: DEPTH/RATE (these are modulation).
- Mood: WET MOD and LOOP MOD change meaning per mode.

**Audio-thread notes.** No allocations were found in the FX paths. Check two
things:
- `setFxProcessingOrderWithReason` locks and builds strings (OK only off the audio thread).
- The `MODULE_ORDER` fallback order differs from `kDefaultFxOrder` (minor).

### UI / layout / editor

**Layout model.** `InstrumentSceneNode` (`UILayout.h:25`) has:
- bounds normalized 0..1 of the parent
- a layout mode: absolute / row / column / grid / overlay
- flexGrow, a single gap, min/max size, order, visible, styleToken, binding

`resolveBounds` (`UILayout.cpp:679-820`) does not support padding,
align/justify, px or % sizing, shrink/basis, wrap, margin, spans or separate
x/y gaps. It does an O(n²) sibling scan on every call.

**Coverage is about 5%.** The scene has only 12 nodes: the root, a `primary`
row (OSC/FILTER/AMP) and 7 full-size view containers. Header, macro strip,
keyboard, wheels, cards, knobs, buttons and labels have no nodes.
`PluginEditorView.cpp::resized()` hand-lays out 330 lines. The panels hold
roughly 110 more `setBounds` calls. UIConfig.json numbers fill the rest.

**Second flex system.** `FlexStyle` → `juce::FlexBox` (`CardInner.h:37`),
driven by UIConfig.json, lays out card rows. It is the closest thing to real
flex here and is not connected to the scene.

**Designer** (`UILayoutDesigner.*`) is a floating dev window with
**dropdown-only selection**. There is no click-to-pick. Only the 12 region
nodes are selectable: no knob, card, button or keyboard, and no nested
selection. There is no snapping and no reset.

**The fake drag, confirmed.** The default selection is `primary.osc`, whose
parent is a ROW. `resolveBounds` ignores `bounds` for row/column/grid
children (`UILayout.cpp:709+`). Dragging mutates the document and moves the
yellow frame, but the UI does not change. The frame is drawn from raw bounds,
not from the resolved rect, so it can disagree with the real panel. Only
children of absolute parents actually move.

**What works.** The property sliders apply live. Undo/redo is real: a
snapshot stack of 100 entries, with buttons but no shortcuts. Save writes the
JSON. Document validation is solid and tested (`TestsUILayout.cpp`).

**Release separation** works through `PX3_UI_DESIGNER`/`PX3_DEBUG_PANEL`
compile gates. Two leftovers:
- `JUCE_DEBUG ||` paths remain at `PluginEditorConfig.cpp:84/138/215`.
- Release still runs the scene resolve on every `resized()` (cheap but O(n²)).

**Windows.** The only floating instrument window is `GraphRouteWindow`
(`ModPanel.cpp:331`, the ROUTES button). The preset browser, bus-insert sheets
and macro depth panel are already in-window.

**Navigation.** 6 tabs plus settings: OSC/MOD/AMP/FILTER/FX/MIX. Only one
panel shows at a time, except the OSC "composite", which shows
OSC+FILTER+AMP side by side at ≥900×380. Default size 1518×918, limits
980×600–1900×980.

**Styling.** Three parallel systems:
- UIConfig.json (2,984 lines)
- 8 scene style tokens, mostly unused
- about 515 hard-coded colours and about 158 literal font sizes

There is no type scale. Look-and-feels: Knob, MacroKnob, FetPushButton,
Fader, MacroDepthSlider, plus per-panel combos.

| Component | Verdict |
|---|---|
| Scene document pattern (validate/transactions/undo/tests) | Refactor: keep the pattern, replace the schema |
| `resolveBounds` | Replace with a real flex/grid solver |
| Scene JSON content | Replace: must describe the whole UI down to controls |
| Designer window + selection overlay | Replace: in-place click-to-select, frame drawn from the resolved rect |
| Compile-time designer gating | Keep; remove `JUCE_DEBUG` leaks |
| Hand-laid `resized()` across editor/panels | Refactor onto the layout model |
| FlexStyle/CardInner | Merge into the single layout model |
| GraphRouteWindow | Replace with in-window modulation |
| UIConfig + tokens + literal colours/fonts | Merge into one token system with a type scale |
| Look-and-feel classes, preset browser, in-window sheets | Keep (re-skin) |

## Decisions

1. **One layout engine.** Replace `resolveBounds` and the separate
   FlexStyle/CardInner system with a single flex/grid solver. It will be
   Yoga-like and support: direction, wrap, gap x/y, padding, margin,
   align/justify, px / % / flex basis, grow/shrink, min/max, order, and grid
   tracks. Every visible object becomes a scene node with a stable ID: header,
   sections, cards, knobs, buttons, labels and keyboard. Components register by
   ID, and the editor binds `setBounds` from resolved rects instead of
   hand-written `resized()`. Resolution is cached and runs only when the size
   or document changes.
2. **Designer in place.** It is a dev-only overlay on the live editor with
   hover highlight, click-select, Alt/Cmd-click to select the parent, drag and
   8 handles, and snap. The frame is always drawn from the **resolved** rect.
   Dragging a flex child edits basis/size; dragging an absolute child edits
   position. The property inspector is contextual by node kind and may be a
   separate dev window (allowed). Undo/redo uses shortcuts. Save, load and
   reset-to-default are provided. All of it is behind `PX3_UI_DESIGNER`.
3. **No floating instrument windows.** `GraphRouteWindow` will be removed.
   Modulation moves into an in-window MOD page:
   - a patch canvas with sources (sockets) feeding destinations
   - drag-from-source handles onto any knob
   - modulation rings on knobs
   - per-route depth inline
4. **Per-voice modulation.** Add per-voice graph evaluation for ENV, key,
   velocity and slop sources (`ModulationScope::voice` already exists but is
   unused). Global sources stay per block. This is required for envelope
   routing, slop and fine-tune modulation to mean anything polyphonically.
5. **Spread moves to the master bus** as a stereo-field stage with a non-zero
   default. A new Distortion stage joins the FX chain.
6. **Styling.** One token set covers colour, type scale, spacing, knob sizes
   and panel depth, and it replaces the literal colours and fonts. The visual
   language is a VCV-inspired module system: panel rails, screws are optional,
   inset displays, consistent knob family with modulation rings.
7. **Order of work under the owner's limited budget:**
   - First, the concrete DSP correctness fixes that are small and verifiable:
     Rob/Isaac pitch, Spread inert, Doom gain staging, organ click, hard-sync
     range, Digital controls, supersaw label and voice budget, filter
     resonance/key-track, wavetable picker and fallback.
   - Then the layout engine and designer (Phases 2–3).
   - Then the in-window modulation (Phase 6) and the visual redesign
     (Phases 4–5).
   - Then the new DSP models: Uni-Vibe, Juno chorus, Curtis/ARP/own ladder,
     tape wobble/slip, shimmer/IR, distortion.

   Each item is committed separately with tests.
