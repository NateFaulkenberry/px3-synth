# PX3 0.8.0 UI foundation: one layout system and a live designer

This is the layout half of the 0.8.0 reconstruction (decisions 1 and 2 in
`PX3_0.8.0_RECONSTRUCTION_AUDIT.md`). It replaces the old normalized-bounds
resolver and its dropdown-only designer. It does not touch DSP, styling or the
modulation UI.

### The engine

A small Yoga-like subset, implemented directly in `UILayout.cpp`:

- **flex**: `direction` row/column, `wrap`, `gapX`/`gapY`, `padding`, child
  `margin`, `alignItems`/`alignSelf` (start/center/end/stretch), `justify`
  (start/center/end/space-between/space-around/space-evenly), `basis` in
  px/%/auto, `grow`, `shrink` (weighted by basis, as in CSS), `min`/`max`
  width/height in px or %, with the CSS freeze loop so a clamped item hands
  its share back to the others, `order`, and align-content stretch for
  wrapped lines.
- **grid**: `columns` template in px/%/fr/auto, `rows` template (or implicit
  equal rows), gaps, explicit `column`/`row` placement or row-major auto
  placement, `columnSpan`/`rowSpan`.
- **none** (overlay): each relative child fills the content box. Used for the
  overlapping section views.
- **absolute** children of any container: `x`/`y`/`width`/`height` in px or %
  of the parent box; an auto size fills to the far edge.
- `aspect`: the final box is the largest rect of that ratio that fits,
  centred; in a flex row/column an auto main size follows the cross size
  (knobs use `aspect: 1`).
- A flex/grid container whose children are all hidden collapses. This is how a
  cell whose only control a mode hides drops out of its row.

Resolution is cached: `resolve(root)` re-runs only when the root bounds or the
document revision change (the revision also bumps for runtime visibility
changes). Topology (id map, sorted children, depths) is rebuilt on edit, not
on resolve, so a resolve is linear in the node count and allocation-free once
warm (flex scratch is reused; grid placement allocates small vectors).

### Schema v2

`schemaVersion: 2`. Unknown node keys are rejected, as are unknown parents,
cycles, duplicate ids, more than one root, unknown style tokens, `fr` outside a
grid template, a grid without columns, negative grow/shrink/gaps/padding/sizes,
spans < 1 and min > max in the same unit. One node per line, defaults omitted,
so the file diffs well.

```json
{"id": "osc.1.coarse.knob", "parent": "osc.1.coarse", "kind": "control",
 "label": "COARSE", "style": "control.knob", "width": "100%", "maxHeight": 56, "aspect": 1, "order": 1}
```

Node keys: `id parent kind label binding style order visible locked` ·
container: `layout direction wrap gap gapX gapY padding alignItems justify
columns rows` · child: `position x y width height basis grow shrink minWidth
minHeight maxWidth maxHeight margin alignSelf column row columnSpan rowSpan
aspect` · `note` (free text). Lengths: number = px, `"40%"`, `"1fr"` (grid
templates only), `"auto"`. Edges (`padding`, `margin`): one number or
`[top, right, bottom, left]`. Kinds: container, panel, card, control, button,
label, display, decoration (they only decide what the inspector offers).

### What the scene covers

181 nodes:

- `instrument` (column, 16 px padding) > `header` (logo, top menu, gain knob),
  `controls` (macro strip + the `views` overlay), `keys` (wheels + keyboard).
- `views` > `view.osc` (the OSC/FILTER/AMP row: `primary.osc`,
  `primary.filter`, `primary.amp`), `view.mod`, `view.fx`, `view.mix`,
  `view.settings`.
- `primary.osc` > `osc.sub`, `osc.1..3` cards, and inside each card every
  control: power button, mode/vowel/wave dropdown cells, COARSE/SEMI/FINE knob
  cells (label, knob, readout), wavetable table/position, MACRO A/B/C, and the
  wave graph.
- `primary.filter` > routing strip (SERIES/PARALLEL chip, balance label and
  slider) and `filter.1`/`filter.2` cards.
- `primary.amp` > `amp.envelope` card.

Runtime state the file cannot know is applied by the editor as *runtime
hidden* flags (not saved, not undoable): the macro strip on SETTINGS, which of
`primary.osc/filter/amp` show (all three on OSC at >= 900x380 - the composite -
otherwise the selected one), and any control whose owner hid it (mode-dependent
knobs, the routing strip before it is attached).

### Binding

`PX3SynthAudioProcessorEditor::bindSceneComponents()` registers components by
node id (`PluginEditorConfig.cpp`). `applySceneLayout()` sets the runtime
flags, resolves once, and `SceneBinding::apply` sets every bound component's
bounds parents-first (converting from editor coordinates to each component's
parent). The editor's `resized()` no longer does layout arithmetic for any
scene node; panels that the scene places (`OscPanel`, `FltPanel`, `AmpPanel`,
and the oscillator cards) ask the editor to relayout (`requestSceneLayout`)
instead of placing children themselves.

Layout never touches sound: the scene is its own file, separate from presets
and state, and the designer only edits the document. A test drags a live node
and compares all 401 parameters before and after.

## Release cost

- `UILayoutDesigner.cpp` is only added to the sources when `PX3_UI_DESIGNER`
  is ON; `UILayoutEditing.cpp` and the document's mutation/undo API compile
  to nothing unless `PX3_UI_DESIGNER` or `PX3_UNIT_TESTS`.
- Release builds read the shipped scene from BinaryData and never from disk.
  The `JUCE_DEBUG ||` path in `resolveUILayoutFile` is gone; only designer
  builds look for a source-tree file.
- Resolve runs from `resized()`, on a section change, and when a component's
  visibility changes; it is cached in between.

## Using the designer

1. Configure a designer build (keep plugin copying off):
   ```bash
   cmake -B build/ui-designer -G Ninja -DCMAKE_BUILD_TYPE=Release \
     -DPX3_UI_DESIGNER=ON -DPX3_COPY_PLUGIN_AFTER_BUILD=OFF
   cmake --build build/ui-designer --target PX3Synth_Standalone
   ```
2. Run the standalone from the repository root (so it finds
   `shared/UI/Style/InstrumentScene.json`; or set
   `PX3_INSTRUMENT_SCENE_PATH`). Open MENU > UI Designer.
3. On the editor: hover shows the node under the cursor (cyan). Click selects
   the deepest node (yellow frame with 8 handles, id, size and role). Click
   again inside a selected container to drill down; Alt- or Cmd-click, Esc, or
   the Parent button selects the containing node.
4. Drag the body to move, a handle to resize. What changes:
   - absolute child: `x`/`y`/`width`/`height`, units kept (a % stays a %);
   - flex child: moving along the row/column reorders it (`order`); resizing
     along the main axis sets `basis` so the resolved size lands under the
     handle (grow kept; if the node is the only grower its grow is set to 0);
     resizing across sets `width`/`height`;
   - grid child: cell and spans; overlay child: margin and size.
   Locked nodes cannot be dragged. Snap (4 px) applies to dragged edges.
5. The inspector window shows only the fields that apply (container fields,
   then the child fields for the node's role, then size/min/max/margin/aspect;
   `binding` for controls). Edit a field and press Return. Drags stream into
   the fields; field edits relayout immediately.
6. Undo/redo: Cmd-Z / Shift-Cmd-Z on the overlay, or the buttons. A whole drag
   is one step. Order -/+ reorders, Hide/Show and Lock toggle the flags.
7. Edit: off lets you play the synth with the selection still drawn.
8. Save writes the user layout, `~/Library/Application Support/P(X3)/Layouts/
   InstrumentScene.json`. Save default writes the source-tree
   `shared/UI/Style/InstrumentScene.json` (commit it to ship the change). Load
   opens a file chooser in the Layouts folder. Reset restores the compiled-in
   shipped default. Load and Reset are undoable.

Choice made: release builds use only the compiled-in default; a user layout
file is a designer-build artefact and is never read by a shipped plugin.

## Verification

- `PX3Tests uilayout`: 17 engine tests (flex sizing, gaps/padding/margins,
  min/max redistribution, weighted shrink, percent basis, all justify modes,
  align/self/column, wrap with cross gap, order, absolute px/%, grid tracks/
  spans/placement, aspect, hidden/runtime-hidden/collapse, caching, strict
  validation, JSON round trip, coalesced undo) and 10 designer tests (flex
  drag changes basis and resolved rect, sole grower, absolute move keeps
  units, corner resize with snap, reorder, lock, hit test, one-step
  undo/redo, save/load round trip, live drag moves the real component, layout
  edits change no parameter).
- `PX3Tests uisnapshot <dir> [w h]`: per-section PNG and a dump of every
  visible component's bounds. At 1518x918 with UIConfig present, every section
  matches the pre-change editor within 1 px (float edges vs. the old integer
  arithmetic: the wheel strip is 186 px instead of 185, the second oscillator
  card one pixel right).

- Full `PX3Tests` (release config, `PX3_UI_DESIGNER=OFF`): 1638 passed, 0 failed.
- Builds: `PX3Synth_Standalone` + `PX3Tests` in a designer config
  (`PX3_UI_DESIGNER=ON`) and a release config, both with
  `PX3_COPY_PLUGIN_AFTER_BUILD=OFF`.
- Release binary: `nm -C "PX3 Synth" | grep -cE
  "LayoutDesigner|LayoutInspector|layoutedit::|replaceFromJson|beginTransaction"`
  gives 0 (the designer build: 365). `SceneBinding::apply` is present in both.
- The designer standalone was built but not launched (no interactive session);
  its first interactive use should be checked by hand.

## Still hand-laid (not yet scene nodes)

- Inside the filter cards: type dropdown, cutoff/resonance, the comb knobs and
  polarity switch (`FltPanel::layoutCardControls`, CardInner rows). The cards
  themselves and the routing strip are scene nodes.
- Inside the AMP envelope card: graph, ADSR knobs and mode selector
  (`EnvelopeComponent`, which the MOD envelopes share).
- The insides of MOD, FX, MIX and SETTINGS panels, the top menu bar's tabs and
  preset cluster, and the macro strip's knobs (each is a leaf node).
- Overlays that float above the layout: preset browser sheet, update notice,
  macro depth panel, bus insert sheets, spark overlay (derived from `keys`).
- `FlexStyle`/`CardInner` therefore still exist for those cards and for
  standalone use of the oscillator cards (outside the editor they lay
  themselves out). The scene took over the card geometry UIConfig gave the
  OSC cards (`cards.osc.cardInner`, `cards.subOsc.cardInner`): those UIConfig
  rows no longer move anything in the editor.

## Known issues

- The OSC/FILTER/AMP composite (OSC tab at >= 900x380) gives each oscillator
  card about 138 px: knobs render at 27-29 px and the COARSE/SEMI/FINE
  captions do not fit. This is how the editor already looked; the suite never
  saw it because the test binary never found the scene before (release
  builds only looked in a plugin bundle). `Labels_EveryChipLabelCanBeReadInFull`
  now checks the cards off the OSC tab. A layout decision for the redesign.
- With the scene compiled in, the AMP card shows the scene's hardware
  faceplate (short ADSR captions, scene text colour) in the test binary too;
  three envelope tests accept that presentation.
- In vowel modes the mode cell keeps its 116 px basis beside the 84 px vowel
  cell (CardInner shrank it to 84); flex has no "if a sibling is shown" rule.
- The designer UI itself (overlay, inspector) is compiled and linked in the
  designer build but has no automated UI test; its editing logic is tested
  through `UILayoutEditing`.
